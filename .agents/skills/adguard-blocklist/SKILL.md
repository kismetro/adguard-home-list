# AdGuard 차단 관리

이 저장소 안에서만 사용한다. 저장소 루트의 `AGENTS.md`를 정책의 기준으로 삼고 `jun-block.txt`를 변경 대상으로 삼는다. 전역 설정, 실행 중인 AdGuard, 공유기를 직접 변경하는 권한은 포함하지 않는다.

## 주소 조사와 범위

- 요청 주소의 실제 본문, 외부 링크, 리다이렉트를 확인한다. 접근 제한 시 검색과 다른 공개 출처로 보완한다. 단순 연결, 자동 평판 점수, 공유 IP만으로 위해 사이트를 확정하지 않는다.
- 명시적 차단 대상은 사용자 지정으로 처리할 수 있다. 연관 사이트는 실제 성인 콘텐츠·도박·불법 복제 등의 근거가 확인된 경우 추가한다. 조사 결과와 정책상 지정 차단을 구분한다.
- 글에서 소개한 대상을 막으라는 요청과 글 자체를 막으라는 요청을 구분한다. 공용 CDN, 전체 플랫폼, 앱 스토어를 부수적으로 차단하지 않는다.
- 사용자는 개별 주소뿐 아니라 같은 서비스의 숫자·TLD·서브도메인 변형 차단을 원한다. 브랜드 문자열 전체 차단을 명시하면 `/brand/$important`를 사용한다. `wang`·`toon` 같은 일반 문자열은 모든 포함 도메인으로 넓히지 말고 서비스 이름 및 숫자 형태에 경계를 둔다. 확인된 별도 서비스 도메인은 따로 처리한다.
- 현재 접근 불가와 서비스의 영구 종료는 구분한다. 근거가 부족한 연관 주소는 추가하지 않고 미확인 범위를 알린다.

## 규칙 작성

- 먼저 기존 규칙의 의미상 포함 여부를 확인한다. 넓은 규칙을 추가하면 완전히 포함되는 좁은 규칙은 제거하되 필요한 예외를 유지한다.
- 일반 도메인: `||example.com^$important`.
- 숫자·TLD 변형: `/(^|\.)brand[0-9]*\./$important`. 원형까지 포함할지 숫자 필수인 `+`를 사용할지는 요청 범위에 맞춘다.
- 한글 도메인은 IDNA/Punycode로 변환한다. 한글 뒤 숫자를 붙이면 Punycode 자체가 달라지므로 인코딩 문자열 끝에 숫자 와일드카드를 단순히 붙이지 않는다. 실제 인코딩 표본으로 검증하고 지원하는 숫자 범위를 명시한다.
- 분류, 출처 URL, 접근 제한 등 중요한 조사 한계를 짧은 주석으로 남긴다.

## 검증과 반영

- 새 규칙의 대상·서브도메인·숫자·TLD 변형을 양성 표본으로, 비슷한 정상 도메인을 음성 표본으로 확인한다. 중복과 정규식 문법 및 `git diff --check`도 확인한다.
- Python 정규식 검증은 로컬 보조 검사다. AdGuard Home의 실제 엔진·캐시·클라이언트 설정·단말 동작까지 검증했다고 표현하지 않는다.
- `git status`와 diff를 확인하고 관련 파일만 명시적으로 stage한다. 기존 미추적 `list.json` 등 무관한 변경은 포함하지 않는다.
- 변경이 있으면 commit하고 현재 브랜치를 원격에 push한다. 실패 원인을 알리고 강제 push하지 않는다. 변경이 없으면 불필요한 커밋 없이 원격 반영 여부를 확인한다.
- 결과는 적용 범위, 중요한 제외·한계, 로컬 검증, 커밋 ID와 push 여부로 간결하게 보고한다.
